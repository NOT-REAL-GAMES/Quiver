# In-engine map editor

Open the console and enter `editor_new` to start with one enclosed 3D sector, a player start and a light. The editor works before a map is loaded. Use `editor_open <name>` to edit a source file from the active game directory's `maps/<name>.map`; compiled BSPs cannot be opened as editable source. Names use letters, numbers, `_` and `-`. Existing Quake brush `.map` files remain editable; `editor_new_brush` creates a legacy brush document.

The editor opens in a perspective view of the actual source faces. Move the camera with `W`, `A`, `S`, and `D`, and use `Q` and `E` to move down and up. Hold Shift to move faster, drag with the right or middle mouse button to look around, and use the mouse wheel to move forward or back. Left-click a sector and drag to move it in the view plane. Shift-drag on the ground plane creates a 128-unit-high box sector on the 16-unit grid; aim downward to reach the ground. `P` places the player start on that plane.

In a sector document, press `F` to enter face mode: click a face and drag vertically to move it along its normal. Press `V` for vertex mode, then select a sector and drag a visible vertex in the view plane. Vertex positions snap to the world grid; dragging near another visible vertex snaps to and merges it, even when that vertex is off-grid. A merge that would make invalid geometry is rejected. Press the same mode key again to return to sector selection. Moving vertices can create sloped surfaces; affected faces are triangulated where necessary. Shared vertices remain connected.

Room-sector vertices at exactly the same source position move together in vertex mode, including vertices in different rooms. Prop vertices remain independent of room and other prop vertices. Nearby vertices remain independent. The editor rejects the entire move if it would make a sector or portal invalid.

Press `K` in the perspective view for the knife, then click near two boundary edges of the same face to split it. The endpoints snap along the edges to the grid; a preview shows the cut before the second click. Press Escape to cancel a pending cut, or `K` to leave knife mode. The cut must stay inside the face. The resulting faces can be edited independently, and cuts through a portal are mirrored on the connected sector. Knife cuts can be undone and redone.

To connect adjoining volumes, select a face in face mode and press `L`, then select a coplanar, oppositely facing face on the other sector and press `L` again. Repeatedly click within a small area to cycle through faces under the pointer; Ctrl-click also cycles them. The common area becomes a portal; a smaller face can cut a doorway in a larger one. Coplanar pieces produced by splitting a face are linked together. Select an existing portal and press `U` to close it. Set `editor_texture` in the console, select a face and press `T` to apply that material.

Linking automatically joins matching portal vertices and cleans up compatible fragments around the opening. Intentional knife cuts and material boundaries are preserved. To clean up links created before this feature, use `editor_cleanup_links` in the console. That command can also remove redundant points on straight portal edges; use Ctrl+Z to undo it if you wanted to keep one for later editing.

The viewport shows the outside outline of each portal opening rather than internal edges introduced by linking. Select a face in face or knife mode to see that face's own boundary.

Older sector files do not record which triangles came from a split face. The editor recovers this information for an unambiguous pair that forms a convex quad, and saves the recovered grouping. Ambiguous older triangulations remain separate faces so linking one cannot unexpectedly open neighboring walls.

Press Tab to cycle through perspective, top (X/Y), front (X/Z), and right (Y/Z) views. Press `1`, `2`, `3`, or `4` to select top, front, right, or perspective directly; the view buttons also select them. In an orthographic view, left-click selects and drags a volume, its lower-right handle resizes it, Shift-drag creates a box, right or middle drag pans, and the mouse wheel zooms around the pointer. Press `V` to edit vertices on the visible plane. New side-view boxes have 128 units of depth, centered on the selected sector or view focus. `[` and `]` move a selected volume or light along the hidden axis (Z in top, Y in front, X in right); Shift plus those keys adjusts a volume's upper depth bound. In perspective, those keys adjust Z as before. Delete removes the selected volume or light. `Ctrl+Z` and `Ctrl+Y` undo and redo.

Press `G` to cycle the type created by Shift-drag: a world sector, `prop_static`, `prop_dynamic`, or `prop_movable`. Props can be placed inside a room. Select an existing sector and press `O` to cycle its type; a sector with a linked portal must be unlinked before it can become a prop. Each prop is one editable sector, with its own faces and materials. Its vertices remain independent of coincident room or other prop vertices.

The Properties inspector appears on the right in both 2D and 3D views; press `I` to hide or show it. Select a `prop_static` and use its **Collision** checkbox to control whether players and other entities collide with it. Collision is enabled by default, including for older maps. The setting is saved with the sector and participates in undo, redo, and duplication.

Select a world sector or brush to edit the map-wide **World script (.qs)** path. Enter a path relative to the current game directory, such as `scripts/ripple.qs`, and press Enter to save it; an empty path removes the script. The same property can be changed through `editor_script scripts/ripple.qs`. Scripted F9 playtests compile a snapshot of the script into a separate game package and open a second game window. Press F9 in that window to end the playtest and return to the editor. Script compilation errors appear in the editor console. For the language and standalone package build, see [QuiverScript](quiverscript.md).

Static props are baked into the world BSP for rendering and lighting; they remain separate editable sectors in the source map. With collision enabled they also contribute solid collision and BSP visibility occlusion. With collision disabled, they compile as non-solid world detail so players can move through them safely; they do not block precomputed BSP visibility. Dynamic props move with a configured linear velocity and push entities they encounter; to set it, select the prop, open the console with Shift+Escape, and enter `editor_prop_velocity <x> <y> <z>` in Quake units per second. Movable props fall under gravity and can be pushed by walking into them; the same command sets an initial velocity. The native fallback uses the prop's axis-aligned bounding box for movable collision, and does not support rotating props. Dynamic props use Quake's translating pusher behavior and do not stop automatically at world walls. A mod that provides its own dynamic or movable prop spawn function controls its behavior instead.

Press `H` with the cursor in any view to create a point light. In perspective it is placed in front of the surface under the cursor; in an orthographic view it is placed on the visible axes at the cursor, with depth from the selected sector or view focus. Click a light marker to select it and drag to move it. Select a light and use the Properties inspector’s **Red**, **Green** and **Blue** fields to change its color (0–255 per channel; 255, 255, 255 is white). Press **Enter** to apply a channel; the swatch shows the saved color. Color edits preserve the other light properties and support undo/redo, duplication, and saving in both MAP and QSECTOR documents. Imported normalized or byte-valued colors are recognized; explicit edits save normalized `_color` and replace the legacy `color` alias. To adjust intensity, enter `editor_light_intensity <value>` in the console; new lights default to 300. Lighting is rebuilt when you start a changed playtest.

Select a light or sector prop and press `Ctrl+D` to duplicate it. The copy is selected and offset by grid-sized steps so it can be moved into place; lights in rooms choose a nearby open position. Light properties and prop materials, type, and velocity are preserved. Duplication participates in undo and redo.

Imported static MDL, MD3 and MD5 models can also be placed through the inspector's **Place static model** path and **Add model ahead of view** button, or `editor_model progs/sponza.md5mesh`. Select their marker to edit path, origin, angles, scale, skin and mesh collision. Their textured meshes appear in perspective and all orthographic views, with neutral shading and oriented bounds. They share the point-entity move/duplicate/delete/history controls. Playtesting compiles placements and collision triangles into the versioned BSPX extension described in [Compiled static models](static-models.md), without needing a mod spawn function.

Use Shift+Escape to open the console from the editor. Use `editor_save <name>` to save a new source map; `Ctrl+S` saves after a name has been assigned. Save-as does not overwrite an existing file. Opening or creating another map while the current document has unsaved changes is refused; use `editor_open <name> force` or `editor_new force` only to discard those changes.

Press `F9` to switch between editing and playtesting. `Ctrl+P` or `editor_play` also starts a playtest; `editor_return` returns to the editor. Switching to play compiles a changed document in the background and launches it. Compiler messages appear in the console. Playtest files have unique names in the active game's `maps` directory and do not replace the source map. A changed document is recompiled; the last successful build can be reused while the document is unchanged. If the document changes during compilation, that result is discarded. Use `editor_return` to resume editing with the document and undo history intact.

QBSP, VIS and LIGHT are linked into the game executable. The editor runs each stage in an isolated worker using that same executable, keeping the interface responsive and containing compiler errors. A build needs a working C++ compiler and standard library for the embedded tools. If the default compiler lacks C++ headers, configure a fresh Meson build with a working compiler, for example `CXX=/usr/bin/g++ meson setup build-release --buildtype=release`. An existing Meson build keeps its cached compiler, so use a fresh build directory when changing it. An engine-only build can explicitly disable the tools with `-Dembedded_maptools=disabled` (or `EMBED_MAPTOOLS=0` for GNU Make); playtesting is unavailable in that configuration. Set `editor_qbsp` to an explicit executable path only if a different QBSP is needed; VIS and LIGHT still use the embedded tools.

New sector `.map` files use the versioned `QSECTOR 1` source format. Each sector is a closed 3D polyhedron with planar polygon faces; sectors can be concave, stacked, sloped, and connected on faces of any orientation. Faces must form valid, non-self-intersecting shells, and sectors cannot overlap in their interiors. Portals must connect coincident, oppositely oriented faces. The editor validates topology before accepting changes. For playtesting it converts the sector boundaries to a temporary Quake brush map and compiles static BSP2 world geometry, avoiding BSP29's short-coordinate limits; saving preserves the editable sector data and entities. A custom `editor_qbsp` must support `-bsp2` for sector maps. The embedded compiler currently accepts sector coordinates up to ±1,047,552 units; more distant geometry can be edited and saved but cannot yet be playtested.

Legacy brush maps retain their original format. Their top-down view represents brushes by bounds; non-box brushes can be translated, but only axis-aligned six-sided boxes can be resized. QBSP needs matching WAD textures. If a source specifies no WAD, its playtest snapshot uses the bundled placeholder WAD when available; the saved source is not changed. Other textures without a matching WAD may appear missing. The embedded QBSP checks for leaks before playtesting. New maps include a light; existing maps need their own light entities to be illuminated.
